# VA 520 Flow Sensor Tester

🇬🇧 [English README](README.md)

> این یک پروژه‌ی مستقل و متن‌باز (MIT) است و ارتباطی با شرکت CS Instruments ندارد. دفترچه‌ی سنسور در این مخزن نیست.

برنامه‌ی تست برای فلومتر **CS Instruments VA 520** (خروجی Modbus RTU روی RS485، خروجی 4..20 mA و پالس).
نوشته‌شده با **C# / .NET Framework 4.8 / Windows Forms**، بدون هیچ دیتابیسی، و قابل اجرا با **Mono روی Raspberry Pi**.
تمام متغیرهای تست (پورت، baud، parity، Slave ID، ترتیب بایت، timeout، retry، فاصله‌ها، …) روی فرم هستند.

> منبع اطلاعات: دفترچه‌ی `VA 520 EN V1.26` (فصل 10 سیم‌کشی، فصل 11.3.2 رجیسترهای Modbus، فصل 6 و 11.3.6 خروجی 4..20 mA، فصل 11.3.3 پالس).

## ۲. سیم‌کشی سنسور (فصل 10 دفترچه)

کانکتور **A** (M12، A-coding، دید از سمت ترمینال):

| پین | سیم | عملکرد |
|---|---|---|
| 1 | قهوه‌ای | +VB (تغذیه 18…36 VDC) |
| 2 | سفید | RS485 **A** (Modbus +) |
| 3 | آبی | −VB (0 V) |
| 4 | مشکی | RS485 **B** (Modbus −) |
| 5 | خاکستری | 4…20 mA (I+) |

* از یک مبدل **USB ↔ RS485** (ترجیحاً با جهت‌دهی خودکار) استفاده کنید؛ A به A و B به B (اگر جواب نگرفتید A/B را عوض کنید).
* اگر سنسور آخر باس است، ترمینیتور داخلی 120 Ω (DIP switch داخل سر سنسور) را **On** کنید، یا یک مقاومت 120 Ω بین پین 2 و 4 بگذارید.
* تنظیمات کارخانه: **Slave ID = 1، 19200 baud، 8 data bit، parity Even، 1 stop bit، Word order ABCD**.
* اگر مبدل شما جهت ارسال/دریافت را با RTS کنترل می‌کند، در تب Connection گزینه‌ی «RTS controls RS485 direction» را فعال کنید (جهت‌دهی با GPIO پشتیبانی نمی‌شود).

## ۳. اجرا روی ویندوز

* `VA520Tester.exe` را (از Releases یا بعد از بیلد از `dist\`) اجرا کنید؛ فقط .NET Framework 4.8 لازم است که در ویندوز 10/11 هست.
* بیلد مجدد: `build_windows.cmd` یا باز کردن `VA520Tester.csproj` در Visual Studio 2019/2022.

## ۴. اجرا روی Raspberry Pi (Mono)

```bash
# ۱) یک‌بار نصب
sudo apt update
sudo apt install -y mono-complete libgdiplus
sudo usermod -aG dialout $USER     # دسترسی به پورت سریال؛ بعد از این یک بار logout/login

# ۲) کل پوشه‌ی پروژه (یا فقط VA520Tester.exe + VA520Tester.exe.config + run.sh در یک پوشه به نام dist) را به Pi کپی کنید، سپس:
chmod +x dist/run.sh
./dist/run.sh
```

* برنامه نیاز به محیط گرافیکی دارد (دسکتاپ Pi). اگر از راه ssh اجرا می‌کنید `run.sh` به‌صورت پیش‌فرض `DISPLAY=:0` می‌گذارد.
* نام پورت‌ها روی Pi: `/dev/ttyUSB0` (مبدل USB)، `/dev/ttyAMA0` یا `/dev/serial0` (UART خود Pi). نام پورت را می‌توان دستی هم تایپ کرد.
* اگر نخواستید exe آماده را استفاده کنید: `./build_on_pi.sh` برنامه را روی خود Pi با `mcs` کامپایل می‌کند.
* اگر `mono-complete` در مخزن سیستم‌عامل شما نبود، از مخزن رسمی https://www.mono-project.com/download/stable/ نصب کنید.
* پنجره روی صفحه‌های کوچک (مثلاً 800×480) هم باز می‌شود؛ تب Connection اسکرول دارد.

## ۵. راهنمای تب‌ها

بالای صفحه همیشه: **Connect / Disconnect / Start polling / Stop / Read once / Auto-reconnect** و وضعیت اتصال.

### Connection – همه‌ی متغیرهای تست
* **Link:** نوع انتقال (`Serial RTU`، `Modbus TCP`، `RTU over TCP`)، Slave ID، تابع خواندن (03 یا 04)، ترتیب کلمه/بایت (`ABCD / CDAB / BADC / DCBA`)، Address offset (برای سنسورهایی که آدرس‌ها یکی جابه‌جا هستند).
* **Serial port:** پورت، baud (1200…115200)، data bits، parity، stop bits، DTR، کنترل جهت RS485 با RTS و تأخیرهای آن.
* **TCP:** Host، Port، Connect timeout.
* **Timing:** Response timeout، تعداد Retry، سکوت قبل از ارسال، سکوت پایان فریم، مکث بعد از پاسخ، و گزینه‌ی «Skip rest of the cycle after a timeout» (پیش‌فرض خاموش: در هر چرخه **همه‌ی مقادیر تیک‌خورده** درخواست می‌شوند حتی اگر یکی Timeout بدهد؛ اگر روشن شود، بعد از اولین Timeout بقیه‌ی همان چرخه رد می‌شوند و چرخه سریع‌تر تمام می‌شود).
* **Error log / CSV / settings:** حداکثر حجم فایل لاگ، سرکوب خطاهای تکراری، ذخیره‌ی مقادیر در CSV، ذخیره/بازخوانی تنظیمات.
* **Custom channels:** ۴ رجیستر دلخواه (آدرس + نوع) که در لیست Monitor می‌آیند.
* **Limit checks:** حد پایین/بالا برای Flow، Velocity و دمای گاز؛ تخطی در لاگ خطا ثبت می‌شود.

### Monitor
لیست همه‌ی مقادیر سنسور (تیک بزنید تا خوانده شود): Flow در ۱۶ واحد، مصرف (Consumption) در ۸ واحد، سرعت، دمای گاز.
برای هر مقدار: مقدار فعلی، Min، Max، میانگین، زمان و وضعیت. سمت راست: آمار ارتباط (تعداد درخواست، موفق، Timeout، خطای CRC،
Exception سنسور، Retry، درصد موفقیت، زمان پاسخ last/avg/min/max، زمان چرخه) و نمودار روند (trend) مقدار انتخاب‌شده.

### Sensor settings
خواندن و نوشتن رجیسترهای ارتباطی خود سنسور (2001…2005): Modbus ID، Baud، Parity، Stop bits، Word order — تکی یا هر پنج با یک درخواست.
بعد از نوشتن، برنامه پیشنهاد می‌دهد تنظیمات اتصال خودش را هم عوض کند و دوباره وصل شود.
(دفترچه نمی‌گوید تغییرات فوراً اعمال می‌شود یا بعد از Save/ری‌استارت سنسور؛ با این تب می‌توانید خودتان تست کنید.)

### Tools
* **Raw frame:** ارسال بایت‌های hex دلخواه (CRC/MBAP خودکار)، با رمزگشایی پاسخ.
* **Read / write registers:** خواندن هر آدرس (Raw/Float32/UInt32/…)، تکرار با فاصله، نوشتن با تابع 16.
* **Register scan:** اسکن بازه‌ی آدرس‌ها برای پیدا کردن رجیسترهای پاسخگو.
* **Auto-detect (serial):** پیدا کردن baud/parity/stop/ID ناشناخته‌ی سنسور (فقط رجیستر 2001 را می‌خواند).
* **Stress / stability test:** N درخواست پشت‌سرهم؛ گزارش درصد موفقیت، انواع خطا، min/avg/median/p95/max زمان پاسخ و آمار مقدار (نویز)؛ با «Save report» در فایل `TestReport_*.txt` ذخیره می‌شود.
* **Simulator:** شبیه‌ساز VA 520 روی `127.0.0.1` برای امتحان برنامه بدون سنسور، با امکان تزریق خطا (حذف پاسخ، CRC خراب، تأخیر).

### Calculators
* **4..20 mA:** با انتخاب مدل/رنج (جدول فصل 6) و جریان اندازه‌گیری‌شده با مولتی‌متر، دبی معادل و انحراف از مقدار Modbus و بازه‌ی دقت (±1.5 % مقدار ± 0.3 % FS) را حساب می‌کند.
* **Pulse:** فرکانس پالس برای دبی داده‌شده، بررسی حد 50 Hz، تعداد پالس برای حجم/زمان مشخص.

### Log
لیست خطاهای همین نشست، دکمه‌ی «View error log file» (نمایش فایل لاگ داخل برنامه)، «Write test error» (برای دیدن اینکه لاگ کار می‌کند) و ردیابی کامل فریم‌های TX/RX به‌صورت hex.

## ۶. فایل لاگ خطا

فایل **`ErrorLog.txt` کنار خود exe** ساخته می‌شود (اگر پوشه قابل‌نوشتن نباشد، در `~/.local/share/VA520Tester/` روی Linux یا `%LOCALAPPDATA%\VA520Tester\` روی ویندوز؛ مسیر دقیق در تب Log نوشته شده). هر خطا یک خط:

```
No | Code | Text | Time | Date
0001 | E1002 | Flow [m3/h] addr 1100: No response from slave 1 within 1000 ms | 14:32:10.123 | 2026-11-07
0002 | E1003 | CRC error: received 1A2B, calculated 3C4D (...) | 14:32:11.456 | 2026-11-07
```

* **No** = شماره‌ی ترتیبی خطا؛ بین اجراهای مختلف برنامه ادامه پیدا می‌کند.
* **Code** = کد خطا (جدول زیر)، **Text** = متن، **Time** = ساعت (با میلی‌ثانیه)، **Date** = تاریخ.
* فایل بیش از 5 MB (قابل‌تنظیم) به `ErrorLog.txt.old` منتقل می‌شود.

| کد | معنی | کد | معنی |
|---|---|---|---|
| E1001 | باز نشدن پورت | E1011 | مقدار خارج از حد (Limit) |
| E1002 | Timeout (سنسور جواب نداد) | E1012 | خطا در نوشتن رجیستر |
| E1003 | خطای CRC | E1013 | خطای پیش‌بینی‌نشده‌ی برنامه |
| E1004 | پاسخ از Slave ID اشتباه | E1014 | خطا در فایل تنظیمات |
| E1005 | کد تابع اشتباه در پاسخ | E1015 | خطا در فایل CSV |
| E1006 | فریم کوتاه/ناقص | E1016 | اتصال برقرار نیست |
| E1007 | خطای I/O پورت | E1018 | ورودی تستی دستی |
| E1008 | خطای اتصال TCP | E1019 | خطای شبیه‌ساز |
| E1009 | MBAP نامعتبر | E1101…E1111 | **Exception خود سنسور** = 1100 + کد Modbus (مثلاً E1102 = Illegal data address) |
| E1010 | مقدار نامعتبر (NaN/Infinity) | E1000 | خطای عمومی (مثلاً «N خطای تکراری سرکوب شد») |

| آدرس | مقدار | آدرس | مقدار |

| 1132…1172 | Flow ltr/h · Nltr/h · ltr/min · Nltr/min · ltr/s · Nltr/s | 1346 / 1354 | Velocity m/s · Nm/s |
| 1180 / 1188 | Flow cfm · Ncfm | 1362 / 1370 | Velocity ft/min · Nft/min |

## ۸. روش پیشنهادی برای تست یک سنسور

1. **Connection:** پورت و پارامترها را بگذارید (پیش‌فرض‌ها = تنظیمات کارخانه). اگر نمی‌دانید → Tools ▸ **Auto-detect**.
2. **Connect** ▸ تب **Sensor settings** ▸ «Read current values» (اتصال و ID را تأیید می‌کند).
3. **Monitor** ▸ **Start polling**: Flow / Velocity / Temp / Consumption را ببینید؛ بدون جریان باید Flow≈0 باشد (در غیر این‌صورت Zero-point سنسور را طبق دفترچه 11.3.1.5 تنظیم کنید).
4. **Stress test** (مثلاً 5000 درخواست): درصد موفقیت و زمان پاسخ؛ برای خطاها لاگ را ببینید. با تغییر Timeout/Retry/Gap اثر را بسنجید.
5. **Limit checks** را روشن کنید و چند ساعت polling با **CSV log** بگیرید (soak test).
6. **4..20 mA:** با مولتی‌متر جریان را بخوانید و در Calculators ▸ 4..20 mA با دبی Modbus مقایسه کنید.
7. **Pulse:** برای دبی/مقدار پالس انتخابی، فرکانس و تعداد پالس مورد انتظار را در Calculators ببینید و با شمارنده‌ی خودتان مقایسه کنید.

## ۸-ب. اگر سنسور جواب نمی‌دهد (عیب‌یابی)

اول تب **Log ▸ Trace every TX / RX frame** را روشن کنید؛ برای هر درخواست `TX ...` و `RX ...` (یا `RX (no bytes received)`) دیده می‌شود.

| نشانه | معنی و کار |
|---|---|
| فقط **Timeout** و `RX (no bytes received)` | سنسور ساکت است: **Slave ID** (روی نمایشگر سنسور، صفحه‌ی اصلی؛ پیش‌فرض 1)، **Parity** (پیش‌فرض کارخانه **Even**، نه None)، baud، جابه‌جایی **A/B**، تغذیه 24 V |
| باز هم ساکت، مبدل جهت‌دهی خودکار ندارد | گزینه‌های **Set DTR high** و **Keep RTS high** (بسیاری از برنامه‌ها مثل QMaster این دو خط را فعال می‌کنند) یا **RTS controls RS485 direction** را امتحان کنید |
| RX **عیناً همان TX** است، یا برنامه‌ی دیگری `Invalid PDU` می‌دهد | مبدل درخواست را echo می‌کند. گزینه‌ی **Converter echoes my request: remove the echo** را روشن کنید. اگر بعد از حذف echo باز هم جوابی نیامد، سنسور ساکت است (به ردیف اول برگردید) |
| `E1003` (CRC) یا `E1006` (فریم کوتاه) با بایت‌های درهم | baud/parity اشتباه، کابل طولانی یا بدون ترمینیتور، جهت‌دهی دیرهنگام مبدل |
| `E1102` (Illegal data address) | ارتباط برقرار است؛ **Address offset** را 1 بگذارید یا با Register scan آدرس‌ها را بررسی کنید |

برنامه‌ی شبیه‌ساز (Tools ▸ Simulator) گزینه‌ی «Echo every request first» دارد تا رفتار echo را بدون سخت‌افزار ببینید.

## ۹. محدودیت‌ها و آنچه تست شده

* ✅ تست‌شده: کامپایل با C# 5 روی .NET 4.8، ۵۷ تست خودکار هسته‌ی پروتکل (CRC، حذف echo، ترتیب بایت‌ها، RTU، MBAP، Exception، نوشتن رجیستر، Retry، لاگ خطا، Poller) روی شبیه‌ساز، و اجرای رابط روی ویندوز با شبیه‌ساز (اتصال، polling، آمار، لاگ، Raw frame، Read، Scan، Stress test، خواندن Sensor settings).
* ⚠️ دکمه‌های **Auto-detect** (نیاز به پورت سریال واقعی) و **Write** (با پنجره‌ی تأیید) فقط در سطح هسته تست شده‌اند، نه با کلیک روی فرم.
* ⚠️ **تست‌نشده:** اجرا روی **Mono / Raspberry Pi** و ارتباط با **پورت سریال واقعی و سنسور واقعی** (در محیط ساخت، نه Mono بود و نه سخت‌افزار). کد فقط از بخش‌های ساده و سازگار WinForms/SerialPort استفاده می‌کند، ولی اولین اجرا روی Pi را حتماً امتحان کنید و اگر مشکلی بود لاگ/متن خطا را بفرستید.
* دفترچه رجیستر وضعیت/خطاهای سنسور (Heater Error، Low Voltage، …) را معرفی نمی‌کند (فقط روی نمایشگر سنسور دیده می‌شوند)؛ بنابراین برنامه آن‌ها را نمی‌خواند. مقادیر بیشتر در سند جداگانه‌ی سازنده (`VA5xx_Modbus_RTU_Slave_Installation`) آمده؛ با ابزار **Register scan** و **Custom channels** می‌توانید رجیسترهای اضافه را کشف و مشاهده کنید.
* خروجی پالس و 4..20 mA را برنامه مستقیماً اندازه نمی‌گیرد (نیاز به سخت‌افزار جدا دارد)؛ فقط ماشین‌حساب مقایسه دارد.
* مصرف (Consumption) در دفترچه فقط «قبل از ممیز» (UInt32) تعریف شده است.
